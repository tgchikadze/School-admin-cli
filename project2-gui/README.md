# Project 2 – GUI (Flet)

Графический интерфейс для системы управления школой в рамках монорепозитория **School Admin System**. 
Проект реализован на Flet и поверх логики Project 1 (CLI) предоставляет удобный GUI для работы со школьниками,
классами и квитанциями. Реализована дополнительная логика для расчета стоимости обучения для 11 класса 
в зависимости от выбранных предметов ЕГЭ.
GUI работает с имитацией базы данных на JSON.

## Возможности

- Управление учениками:
  - просмотр списка учеников
  - добавление, редактирование, удаление
  - фильтрация и поиск
- Управление классами:
  - загрузка данных из JSON
  - отображение информации по классам
- Выбор экзаменов (для 11 класса):
  - выбор экзаменов выпускниками
  - сохранение выбора в JSON
- Работа с квитанциями:
  - генерация одиночных PDF-квитанций
  - пакетная генерация квитанций с фильтром по классам
- Общие возможности:
  - единый GUI на Flet
  - валидация ввода и обработка ошибок
  - работа с локальными JSON-базами данных

## Установка и запуск

1. Клонируйте монорепозиторий и перейдите в ветку `features/gui`:

   ```bash
   git clone https://github.com/tgchikadze/School-admin-cli
   cd school-admin-system
   git checkout features/gui
   ```

2. Создайте и активируйте виртуальное окружение (по желанию):

   ```bash
   python -m venv venv
   venv\Scripts\activate
   ```

3. Установите зависимости из монорепозитория:

   ```bash
   pip install -r /requirements.txt
   ```

4. Запуск Flet-приложения:

   ```bash
   cd project2-gui
   python run_gui.py
   ```

   После запуска откроется окно приложения с основным меню и страницами.

## Основные страницы GUI

### Страница Редактирования БД учеников

- Отображает таблицу студентов из `students.json`.
- Позволяет:
  - добавлять нового ученика;
  - редактировать существующие записи;
  - удалять запись об ученике;
  - фильтровать по ФИО, классу и номеру договора;
  - позволяет массово добавлять записи из csv с проверкой на дублирование (директория выбирается пользователем);
  - позволяет экспортировать БД или отфильтрованную часть в csv;
  - полностью очищать БД.

### Страница поиска

- Поиск школьников по ФИО, классу или номеру договора.
- Поддерживает сброс и массовую генерацию квитанций по найденным записям.

### Две страницы для генерации квитанций

- **Генератор 1 квитанции**:
  - создание одиночной квитанции по выбранному школьнику;
  - генерация PDF через общую логику из `core/receipt/generator.py`;
  - сохранение PDF (директория записи  PDF выбирается пользователем).
- **Массовая генерация квитанций в многостраничный pdf**:
  - массовая генерация квитанций (полный или выборочный вывод записей, ручной выбор из списка);
  - сохранение PDF (директория записи  PDF выбирается пользователем).

### Страница выбора ЕГЭ

- Формирование списка экзаменов для каждого выпускника согласно его заявлению.
- Сохранение результата в `exam_choices.json`.

## Работа с данными

- Источники данных проекта — JSON-файлы в `core/data`:
  - `students.json` — школьники (ФИО, класс, наличие задолженности (компенсация))
  - `classes.json` — классы (к ним привязан список предметов и стоимость обучения для 7-10 классов);
  - `exam_choices.json` — выбор экзаменов для каждого 11-классника.
- Для каждого типа данных есть отдельный модуль:
  - `student_db.py`
  - `classes_db.py`
  - `exam_choices_db.py`

Каждый модуль отвечает за:
- загрузку и сохранение данных;
- базовые операции;
- обработку ошибок (отсутствие файла, некорректный JSON и т.п.).

## Тестирование

1. Запуск тестов для базы данных:

   ```bash
   cd project2-gui
   python -m unittest discover tests -v
   ```

2. Тесты покрывают:
   - корректную загрузку и сохранение данных JSON;
   - операции добавления, обновления и удаления записей;
   - обработку ошибок (не найден файл, битый JSON и т.д.).
